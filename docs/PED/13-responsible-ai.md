All three members use AI assistants. AI output is not authoritative and does not transfer accountability [1, §10]. The control (DEC-004): material contributions are registered with the verification performed; the pull request template requires an AI declaration the reviewer checks; any member may be asked to explain any AI-assisted artefact, including one they did not author.

> **AI-002 — a verified example.** A generated candidate requirement set was used as a starting point and was not accepted as written. Verified: every requirement traced back to a Master Project Brief §3 capability or §2 problem; anything untraceable was deleted. Changed: nine NFRs rewritten for using unmeasurable language, which fails the verifiability standard in [3]. Rejected: AI-based automatic triage — no stakeholder need, no definable acceptance criterion, and it would place an unverifiable component on the accountability path. Recorded as SCOPE-O-07 so the reasoning survives. Cross-checked: a second model (AI-003) found the original NFR-001 stated no concurrency and no data volume, making it untestable.

The register records what was rejected and changed, not only what was used. A register listing only successes evidences record-keeping, not verification.

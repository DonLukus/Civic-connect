### 2026-10-18 - Administration and password reset: provisioning, users and roles, categories, reset links (FR-001, FR-004, FR-023, FR-024)
**Who:** Don, with Claude Code assistance (AI-060) - **Type:** feature, tests
**What:** Added `AdminService` (Administrator only): create an account with exactly one role and no chosen password (the person sets their own through a single-use 72-hour link), change roles, deactivate and reactivate accounts, with every change in the append-only `admin_audit` table; the last active Administrator cannot be demoted or deactivated and nobody can deactivate themselves. Added category administration: create, rename, change the target time, deactivate and reactivate, and delete only when no request uses the category. Added `PasswordResetService` and the `/forgot-password` and `/reset-password/<token>` pages: tokens are stored only as hashes, single use, expire after 60 minutes, and a new request cancels the old link; the email goes through the existing outbox, which scrubs the token after sending; the form gives the same answer for unknown addresses. New setting `APP_BASE_URL`. Pages: `/admin/users`, `/admin/categories`, Administrator navigation and landing tiles.
**Evidence:** `tests/test_m4_admin.py` (63 cases): positive, negative and authorization checks for every operation (Requester, Staff and Manager are refused; sessions of deactivated users stop working; deactivated Staff assignments stay visible to the Manager and can be reassigned), audit rows, token lifecycle (use once, expiry, wrong token, cancelled by a newer request, weak passwords), email delivery with the link and scrubbing, and the routes including CSRF. Full-suite and Ruff results are in the PR.
**Review:** Needs two non-author approvals. Not claimed: external email delivery, login or reset rate limiting (still absent), revoking existing sessions when a password is reset (sessions are cookie-based).
